When UMAP Lies, Part 5: No Loss Function, No Validation

UMAP is non-parametric, fits a graph rather than the data, and no held-out set can choose between its hyperparameters

UMAP returns coordinates for the points it is given and nothing more. It minimises a cross-entropy between two fuzzy simplicial sets, not a reconstruction or prediction loss on the data. Every hyperparameter setting completes without error, no dev set can rank them, and infinitely many settings are equally acceptable. Demonstrated on train/dev/test splits of synthetic data.

UMAP returns coordinates for the points it is given, and nothing more. It has no parameters that generalise to new data, no reconstruction loss to score on held-out data, and therefore no validation criterion that can choose between its hyperparameters. This post shows why, on synthetic train/dev/test splits where the answer is known.

The series so far measured what a 2-D map keeps (Part 1), how dimension breaks it (Part 2), how settings and seeds move it (Part 3), and which visual features it can support (Part 4). This part takes a step back: it asks what kind of object a UMAP embedding is, and what that means for trusting it.

1 What UMAP learns

UMAP builds a fuzzy simplicial set from the high-dimensional data — local connectivity controlled by n_neighbors — and a matching fuzzy simplicial set from the 2-D coordinates, controlled by min_dist and spread. It then minimises the cross-entropy between the two sets.

There are no parameters beyond the coordinates themselves. The result is a set of 2-D coordinates for the training points only. UMAP is non-parametric: there is no function \(f: \mathbb{R}^D \rightarrow \mathbb{R}^2\) learned from the data that you can apply to a new point.

umap-learn does offer transform, an approximate out-of-sample extension that places new points by relating them to the training graph. It is not a fitted parametric model, and it does not invert the embedding. There is no inverse_transform: you cannot go from coordinates back to data.

2 No reconstruction loss

Because there is no function and no inverse, UMAP produces no reconstruction of the data and no reconstruction error. PCA minimises reconstruction error; an autoencoder minimises reconstruction error; UMAP minimises cross-entropy between two graphs.

That graph objective always converges toward zero for every hyperparameter setting, so it cannot rank settings either. There is no loss on held-out data at all: nothing to compute on dev or test, nothing to compare. A dev set can measure how well a supervised model predicts, but it cannot measure how well UMAP embeds, because there is nothing to predict and nothing to reconstruct.

3 Infinitely many settings are acceptable

Every combination of n_neighbors, min_dist, spread, metric, init and seed runs to completion and returns a 2-D layout. None is rejected by a held-out loss. Because there is no validation criterion, choosing hyperparameters is choosing by appearance — “this looks right” — which is not validation.

The demonstration below fits UMAP to the same training data under four settings. All four complete; all four drive the graph objective toward zero; none is wrong by any loss the method exposes.

All four settings expose nothing to compare them against. The trustworthiness and continuity scores below are input-space scores computed on the training data itself — they are not held-out reconstruction losses. Every setting keeps neighbourhoods well (scores around 0.94–0.96), yet they rank differently: the leader on trustworthiness is n_neighbors=15, min_dist=0.00 (0.954) while the leader on continuity is n_neighbors=15, min_dist=0.50 (0.959). No setting leads on both, and none of these scores is computed on held-out data.

4 Train/dev/test cannot validate UMAP

The train/dev/test split is the standard tool for choosing hyperparameters in supervised learning: fit on train, score on dev, confirm on test. It fails for UMAP because there is nothing to score.

The same model, fit on train, places dev and test points through transform. Those placements are not produced by a learned function and they are not stable. Refit with a different seed and the dev points land elsewhere; change n_neighbors and they land elsewhere still. There is no held-out reconstruction error to say which placement is right.

Two consequences follow. First, a dev set cannot pick between n_neighbors=5 and n_neighbors=100: both complete, both “fit” the training graph, and neither has a held-out loss. Second, even after you choose a setting by appearance, you cannot report how much information the embedding threw away on dev or test, because UMAP never reconstructs anything. The number you would report — reconstruction error — does not exist.

5 How it fails on data

The four layouts above already show the failure modes in miniature:

  • Small n_neighbors shatters one population into fragments. A single Gaussian, fit with n_neighbors=5, breaks into several disconnected pieces — the map reports several populations where there is one.
  • Large n_neighbors merges distinct populations. Two well-separated Gaussians, fit with n_neighbors=100, collapse into one cloud — the map reports one population where there are two.
  • Large min_dist drives points apart regardless of truth. It spreads points so far that local structure is washed out, and because there is no loss, no dev set tells you the spreading is wrong.

None of these failures can be detected on a held-out set. The graph objective is satisfied in every case, and there is no reconstruction error to compute on dev or test.

6 Constraints

  • The demonstrations are synthetic, small and clean: independent Gaussian draws at \(n = 600/200/200\). Real populations are skewed, nested and noisy in structured ways, and real failures are messier than these.
  • Only UMAP (umap-learn) is shown. Other graph-based manifold learners differ in detail but share the same structure: they fit a graph, not a reconstruction, and carry the same absence of a held-out loss.
  • Trustworthiness and continuity are input-space scores on the training data. They diagnose a map but do not validate hyperparameters on held-out data.
